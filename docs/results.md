# Results

All numbers here are **measured**, not estimated. Anything not yet measured is
marked as such rather than filled with a plausible value.

**Status:** Stage 2 is complete and final. Stage 1 training was still running
when this document was last written — the CRNN rows below are the honest
in-flight state and are superseded by `outputs/reports/ocr_comparison.md` once
`scripts/finish_run.sh` completes.

---

## 0. What was run, and on what

| | |
|---|---|
| Hardware | Apple M2, 16 GB, PyTorch 2.8.0 MPS |
| Seed | 1337 everywhere (`lasa.common.seed.set_seed`) |
| Drug corpus | 2,000 names — RxNorm `IN`+`BN` (filtered), NLEM India 2022, LASA ground truth |
| LASA ground truth | 164 unique pairs, 272 distinct names, **272/272 present in the corpus** |
| Synthetic data | 59,000 images — 48,000 train / 3,000 val / 4 × 2,000 test |
| Fonts | 25 Google Fonts handwriting faces, all OFL/Apache, SHA-256 pinned |

### A hardware caveat that matters for reading these numbers

`aten::_ctc_loss` **is not implemented for the MPS backend** in torch 2.8.0, and
`PYTORCH_ENABLE_MPS_FALLBACK=1` does not rescue it (it raises at dispatch).
Measured throughput for the CRNN:

| Configuration | Throughput |
|---|---|
| Everything on CPU | 15 img/s |
| Model on MPS, CTC loss on CPU | **111 img/s** |

So training runs the conv/LSTM stack on MPS and hops only the loss to CPU. This
is a local-hardware workaround; on a CUDA T4 the loss runs on device and none of
it applies.

Because of this, **the local TrOCR arm uses `trocr-small-handwritten` on a 3,000
image subset for 2 epochs** — that is what this machine can do in reasonable
time. It is *not* a fair head-to-head against a fully fine-tuned
`trocr-base-handwritten`, and it must not be read as one. The Colab notebook
(`notebooks/colab_train.ipynb`) runs trocr-base on 20,000 images for 3 epochs on
a T4; that is the configuration for a headline comparison.

## 1. Stage 1 — OCR

### The splits, and why there are four

| Split | Words | Fonts | Question it answers |
|---|---|---|---|
| `test_seen` | train | train | Operational accuracy on a known formulary |
| `test_unseen_font` | train | **held out** | Robustness to an unfamiliar hand |
| `test_unseen_word` | **held out** | train | Genuine character-level generalisation |
| `test_hard` | **held out** | **held out** | Both at once |

Verified disjoint: **0** word overlap between `train` and `test_unseen_word`,
**0** font overlap between `train` and `test_unseen_font`, and `test_hard`
disjoint on both axes.

`test_seen` is the operationally relevant number, because a real pharmacy
searches a fixed formulary. `test_unseen_word` is the honest measure of whether
the model learned to read rather than to memorise. Reporting only one would be
misleading, so all four are reported.

### CRNN training curve (validation, greedy decoding)

| Epoch | Train loss | CER | WER | Exact | Epoch time |
|---:|---:|---:|---:|---:|---:|
| 0 | 3.8155 | 86.79% | 100.00% | 0.00% | 852 s |
| 1 | 0.7103 | 11.57% | 57.00% | 43.00% | 436 s |
| 2 | 0.2037 | 5.74% | 34.87% | 65.13% | 398 s |
| 3 | 0.1156 | 4.63% | 27.87% | 72.13% | 402 s |

*(Run in progress at time of writing — 15 epochs scheduled. Epoch 0 is slower
because a concurrent evaluation was competing for CPU.)*

The epoch-0 → epoch-1 cliff is the CTC alignment plateau, not a bug: the model
sits in an all-blank solution until alignment emerges, then collapses error
sharply. An isolated overfit test on 48 real images reached **48/48 exact match**
with loss 11.66 → 0.0012, confirming the wiring before the long run.

### Model comparison

**Pending the completed run** — the final table is generated by
`python -m lasa.evaluation.evaluate` into `outputs/reports/ocr_comparison.md`,
covering every split and, for the CRNN, greedy / beam-10 / lexicon-constrained
decoding as **separate rows**.

Lexicon-constrained decoding is deliberately never merged into the free-decoding
CER. Snapping output to the nearest of 2,000 known drug names is a *different
task* — it is the mode a real pharmacy would deploy, and it will look far better,
but presenting it as the same metric would be the single most misleading thing
this report could do.

| | CRNN (from scratch) | TrOCR (fine-tuned) |
|---|---|---|
| Parameters | **8,379,740** (measured) | 62M (small, local) / ~334M (base, Colab) |
| Checkpoint | ~32 MB fp32 | ~250 MB / ~1.3 GB |
| Decoding | Single forward pass + CTC collapse | One decoder pass **per token** × beams |
| Decode cost (CPU, B=32, T=60) | greedy < 1 ms · beam-10 0.177 s · lexicon 0.826 s | beam-4 generate, measured in the report |

The parameter-count gap is the real finding for deployment: an 8.4M single-pass
model and a 334M autoregressive one are not in the same class for a
pharmacy-counter device (see `docs/deployment.md`).

## 2. Stage 2 — LASA confusion risk (final)

Evaluated against the 164 documented ISMP/FDA pairs using a **seeded,
visual-confusion-biased noise model** (substitution weighted toward handwriting
confusions like `a↔o`, `rn↔m`, `i↔l`, plus deletion, insertion, transposition)
at several error rates. This is a *proxy* for OCR error, not a measurement of
this project's OCR.

### Top-k retrieval

| errors/char | n | Top-1 | Top-3 | Top-5 |
|---:|---:|---:|---:|---:|
| 0.0 | 250 | 98.8% | 100.0% | 100.0% |
| 0.1 | 250 | 99.6% | 100.0% | 100.0% |
| 0.2 | 250 | 96.8% | 100.0% | 100.0% |
| 0.3 | 250 | 90.0% | 97.2% | 98.8% |

Top-3 retrieval holds at 100% up to 0.2 errors/char and only degrades at 0.3 —
roughly one wrong character in every three.

### Pair flagging vs ground truth

A true positive requires the system to **both raise a flag and surface the
documented partner** in the top-k. Flagging without naming the alternative is
not actionable for a pharmacist, so it is not scored as a success.

At the calibrated threshold (yellow = 0.78), 0.2 errors/char:

| Decision rule | Precision | Recall | F1 | False-positive rate |
|---|---:|---:|---:|---:|
| RED only | 96.8% | 18.3% | 30.8% | **1.0%** |
| RED or YELLOW | 91.2% | **97.9%** | **94.4%** | 15.5% |

These are two operating points on one trade-off, and both are reported. RED is
the block-and-confirm gate: high precision, low false-alarm rate, deliberately
conservative about interrupting. RED-or-YELLOW is the advisory tier that catches
almost everything.

### Threshold calibration

`configs/risk.yaml` originally shipped a **provisional** yellow band of 0.62.
Measuring it against 164 ground-truth pairs plus no-partner controls showed it
was badly calibrated:

| yellow band | Precision | Recall | F1 | FP rate |
|---:|---:|---:|---:|---:|
| 0.62 (provisional) | 81.7% | 97.9% | 89.0% | **36.0%** |
| 0.70 | 89.7% | 97.9% | 93.6% | 18.5% |
| **0.78 (adopted)** | **91.2%** | **97.9%** | **94.4%** | **15.5%** |

Raising the band **halved the false-positive rate with no loss of recall**. This
matters more than the F1 gain: at 0.62, roughly a third of unrelated
prescriptions raised an alert, and alarm fatigue is a well-documented way
clinical alerting systems fail — when most alerts are noise, staff learn to
dismiss all of them, including the real ones.

### Signal ablation (0.2 errors/char)

| Variant | Top-1 | Top-3 | Partner surfaced |
|---|---:|---:|---:|
| edit only | **99.2%** | 100.0% | 99.7% |
| phonetic only | 83.2% | 97.6% | 87.5% |
| n-gram only | 90.4% | 98.0% | 92.4% |
| **fused (0.45 / 0.35 / 0.20)** | 96.8% | **100.0%** | 97.9% |

Honest reading: **edit distance alone gives the best Top-1**, and the fusion does
not beat it there. The fusion earns its place on Top-3 and on surfacing the
documented partner, which is what the risk flag actually consumes. If the only
goal were "name the drug", edit distance would be sufficient and simpler; the
phonetic channel is carried because sound-alike confusion is a real clinical
error mode that edit distance ranks too low (`celebrex`/`celexa` scores 0.83 on
edit but only 0.38 phonetically — the two disagree, which is precisely why both
are needed for coverage rather than for accuracy).

### Sample assessments

```
[RED] OCR read 'dobutamin' -> best match: 'dobutamine' (confidence 0.96)
```

Note `losec`/`lasix`: edit similarity is only 0.52, so pure orthographic search

## 3. Bugs found by measurement

Every one of these ran without raising an exception. All are now pinned by tests
in `tests/test_pipeline.py`.

**1. 47.8% of the training set was invisible to CTC.** `resize_for_ctc`
preserved aspect ratio when resizing from stored height 64 to CRNN height 32,
halving the width; combined with the CNN's ÷4 stride, the median image produced
18 frames for a label needing 2L+1 = 21. CTC returns infinite loss for
infeasible samples, `zero_infinity=True` silently zeroes them, and they
contribute **no gradient at all**. The model duly collapsed to predicting all
blanks. Fixed with a 2× horizontal stretch plus a hard per-sample guarantee of
2L+1 frames — infeasibility is now impossible by construction, not merely rare.

**2. Glyph placement corrupted the labels.** `PIL.rotate(expand=True)` re-centres
content in the enlarged canvas. Because each glyph tile is tall and narrow, a
±7° rotation displaced it by nearly a full character width: `xeloda` rendered as
"xepda", `infliximab` lost its `li`. That is mislabelled data, which puts a floor
on achievable CER that no model can cross.

**3. The LASA partner injection was a no-op.** Documented partners were merged
into the candidate list, re-sorted by score, then truncated to k. Since injected
partners score low *by construction* — that is exactly why similarity missed
them — the sort dropped them straight back out. Partner-surfacing was 42.7%;
after the fix, 97.9%, and pair-flagging F1 went 43.3% → 90.6%.

**4. Garbage input read as safe.** A nonsense string returned GREEN with a 0.51
best match. A weak match means "I don't know", which must never render as safe;
it now returns YELLOW with an explicit "treat this as unread" reason.

**5. Collate functions could not be pickled.** Closure-based collates die under
spawn-based DataLoader workers on macOS/Windows (`Can't get local object
'make_ctc_collate.<locals>.collate'`). Converted to picklable classes.

**6. Word segmentation split every pre-cropped word into three.** The dilation
kernel scaled with *image* height, which equals letter height on a tight crop
but is far smaller than it on a full page. Now estimated from the ink itself:
12/12 crops → 1 box, and a multi-word page still segments correctly.

## 4. Limitations

- **Everything is synthetic.** The domain gap between handwriting fonts with
  degradation and genuine prescriber handwriting is **unmeasured**, and is the
  single largest source of uncertainty in this project. No number here should be
  expected to transfer to real chits without a real evaluation set.
- **The local TrOCR arm is handicapped** (small variant, 3k subset, 2 epochs) by
  Apple Silicon constraints. Use the Colab run for a fair comparison.
- **IAM word crops are inferred**, not ground truth: `Teklia/IAM-line` is
  line-level, and the strict crop-count/token-count alignment gate discards
  **69.1%** of lines. The retained 22,506 words are high-confidence, but the
  discard rate is large and writer-independence could not be verified because
  the HF mirror exposes no writer IDs.
- **The LASA pair list is a curated subset** (164 pairs) of published ISMP/FDA
  material, not the full official table. `scripts/ingest_ismp.py` merges the
  official CSV if you obtain it; recall against the complete list is untested.
- **Thresholds are calibrated on this corpus** with a synthetic noise model.
  They would need recalibrating against real OCR error distributions.
- **Not a medical device.** Unvalidated prototype; advisory only.
